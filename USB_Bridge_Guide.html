System Overview

System Overview

The bridge reads a firmware image from a USB pendrive, or receives it from a PC, and transfers it to the Traveo II bootloader over UART using a framed request/acknowledge protocol.

Bridge Firmware Architecture

USB_Bridge.X runs a polled super-loop with two state machines: APP_Tasks() for pendrive (Host) mode and DEV_Tasks() for PC (Device) mode. Libraries are MLA USB and MLA FILEIO; peripherals are generated by MCC.

Detach handling

UART Bootloader Protocol

Binary, framed, half-duplex request/response protocol between bridge and target. The same frames are used on UART2 and on the USB CDC link in Device mode.

5.1Frame format

0xAASTART

LEN_Llength

CRC_Hchecksum
CRC_Lchecksum
0x55END

Table 5-1: Frame fields

OffsetFieldSizeValue / rule
0START10xAA
1MSG_ID1Table 5-2
2LEN2Payload length, big-endian
4PAYLOADLENMessage-specific (5.3)
4+LENCRC2Big-endian; sum of bytes 1 … 3+LEN, modulo 216

crc = MSG_ID + LEN_H + LEN_L;
for (i = 0; i < LEN; i++) crc += PAYLOAD[i];   /* uint16_t, wraps at 0xFFFF */

Firmware Update Sequence

Message sequence for an internal-flash update in Host mode, with retry handling and transfer timing. The target paces the transfer; the bridge never sends ahead of an ACK.

6.2Step table

StepBridgeMessageTarget
1–2Mount FAT, find *.BIN—Application running
3TX filenameUSB_DETECTEDApp sets boot flag, resets
4Wait 1 s, TX againUSB_DETECTEDBootloader in UPDATE MODE
5RXREADY_FOR_UPDATETX
6TX size, blocksHEADERParse, erase app area
7RXREQUEST_DOWNLOADTX
8TX 64 B, seq nDATA_PACKETCheck seq, write flash

PC Update Tools

Python 3 scripts in tools/ send an image through the bridge in USB Device mode and prepare images from MPLAB X HEX output. All scripts need pyserial.

8.1Start the GUI

pip install pyserial                 # one time
python tools/firmware_sender_gui.py  # run from the Marelli workspace folder
  1. Connect the bridge to the PC with no pendrive. RB6 sees VBUS and the bridge starts in Device mode.
  2. In the Marelli Firmware Sender window, select the COM port (Device Manager → Ports) and keep 115 200 baud.
  3. Select the .BIN file and start the transfer. The log shows each step and the progress.

10.2Technical findings

Table 10-1: Code review findings

IDSeverityAreaFindingSuggested action
F1HighPinsRB8 (USBOEN) and RB6 (VBUS) are also planned as SPI SCK and CS.Assign SPI to other RPn pins.
F2MediumHeaderHost mode sends start = 0, end = size, checksum = 0. PC tool sends 0x810000, end, byte sum.Agree one definition with Traveo II team; compute checksum in bridge.
F3MediumBootloaderImage checksum and header addresses are not verified before FLASH_COMPLETE and the jump.Verify checksum; mark app valid only after success.
F4MediumProtocolEXT_FLASH_REQUEST / UNMOUNT_DEVICE functions exist but no state machine uses them.Add external flash states (16-byte payload).
F5MediumLinkerBootloader program region is not limited to below 0x810000.Limit region length to 0xFFFC; check map file.
F6LowFILEIOFILEIO_DriveUnmount skipped in UNMOUNT_DISK ("causes crash").Debug the unmount crash before release.
F7LowTimingPROTOCOL_TIMEOUT_MS = 30 s is a test value; 5 s start-up delay in main().Set from Traveo II erase time; remove delay.
F8LowSpeedAbout 90 debug characters per packet on UART1 roughly double transfer time.Compile out debug prints for production.
F9LowLEDLED_Init() is never called; MCC sets RC1 as input, so status blinks are not visible.Call LED_Init() in main() or configure RC1 as output in MCC.
